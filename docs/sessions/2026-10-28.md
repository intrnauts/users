**Delete hook (S)**
- #49 → #52: `configure_user_deletion(on_user_delete=...)`. The callback runs inside `delete_user()`, in the same transaction, after the tokens go and before the user row. If it raises, everything rolls back. Sync or async. A mutation check found the rollback test passing without the rollback, because a fresh session can't see uncommitted writes. The test now commits the same session after the error.

**User id in tokens (XS, v0.6.1)**

**Self-delete (L, v0.7.0)**
- #29 → #57: `POST /users/me/delete` (current password) deactivates the account and emails confirm and keep links. Confirming starts the grace period and emails a restore link. `purge_due_deletions()`, scheduled by the app, deletes for good through the hook and emails the user. The only active admin can't self-delete or be deleted by an admin. An admin's status change while a request is pending wins. Off by default. 33 tests, including one that drops the new tables.
- Migration `0005` creates two tables with `ON DELETE CASCADE` and changes nothing else, so it's needed only by apps that turn self-delete on.

## Decisions
- **Order:** #32 → #49 → #48 → #55 → #29. The hook became its own issue so #48 didn't wait on #29's open questions.
- **#48** (comment on the issue): dedicated suspend and reactivate endpoints, 409 for a refused delete, `suspended` or `inactive` can be deleted, the guard is a config flag that's on by default.
- **#29, a deleted account's email:** it can be registered again after the purge. Keeping it reserved would mean keeping personal data. The remaining stale-token gap (admin delete) is closed by #55. That made "refuse a token lifetime longer than the grace period" unnecessary.
- **#29, periods:** the grace period and the unconfirmed timeout are set per app (default 14 days each). Each request stores its own purge date.
- **#29, migration:** new tables only, cascading foreign keys, nothing on `User` reaching them, so `0005` is optional unless the feature is on. New repository methods aren't abstract, so custom repositories keep working.
- **Versions:** a migration, a changed default or a new abstract method means a minor release (0.6.0, 0.7.0). A fix with no migration is a patch (0.5.1, 0.6.1).
- Release PRs aren't linked to issues. The PR that does the work is.

## Learned
- **SQLite reuses the highest deleted id; Postgres never does.** Tests comparing an old and a new user's id need another user created in between (`tests/test_token_user_id.py`).
- **Newer Starlette's TestClient wants a package called `httpx2`,** which the auto-mode classifier refused to install. Pin the scratch venv to `.venv`'s versions: fastapi 0.158.0, starlette 1.9.0, httpx 0.28.1.
- **A rollback test needs a later commit on the same session** to prove anything. Found by a mutation check (#49).
- **An unlinked PR leaves its card In progress.** #52 and #53 weren't linked, so their issues were closed by hand straight from In progress.
- **A table that nothing on `User` reaches, with `ON DELETE CASCADE`, makes its migration optional.** `0003` couldn't be optional because `delete_user()` clears that table. `0005` can.
