## Decisions
- Untrusted `create_user()` resets **all three** fields, `status` included, not just `is_superuser` and `roles`. A caller that activates new users must say so with `trusted=True`.
- The vulnerability is tracked in a private advisory, not an issue, because the repo is public.
- No CVE requested. The package isn't on PyPI and is installed from git, so scanners wouldn't flag it. Reconsider when publishing.
- The advisory stays a draft until every consumer is patched and checked.
- Releases are a fast-forward `git push origin dev:master` plus an annotated tag, not a `dev` → `master` PR.

## Learned
- With "Automatically delete head branches" on and `master` as the default, merging a `dev` → `master` PR would delete `dev`. A fast-forward push avoids that.
- Auto mode trusts only the intertainment repo, so pushes, PRs and advisories here are run by hand with `!`.
- `intrnautsai` can't see draft advisories (the API returns an empty list). Add it as a collaborator on the advisory if Claude needs to read it.
- The CVSS field takes only the vector. Anything after it, such as the score, is read as part of the last metric.
- Shell gotchas: a multi-line `--body` breaks when pasted (use `--body-file`); zsh reads `$r:requirements.txt` as the `:r` modifier (write `${r}:`); quote `'v0.4.0^{commit}'`.
