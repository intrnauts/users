# Session record — 2026-11-05

The session built #70 (scoped identity) in the three PRs planned on 2026-11-04 and released it as 0.8.0. Upgrading intertainment-be then showed that migration 0007 failed on a schema not built by `create_all`. That was #83, fixed and released as 0.8.1 the same day.

## Finished

**#70: scoped identity, opt-in (v0.8.0)**
- #79, part 1: accounts have a `scope` (non-null, default `""`), and email and username are unique per scope. Lookups, public flows (register, login, reset, resend verification) and tokens take the scope; tokens carry `scope` next to `uid`. `configure_scope()` turns scopes on, and they're **off by default**: off, a request naming any scope but `""` gets 400. Migration `0007_add_user_scope` is required even with scopes off.
- #80, part 2: with scopes on, a non-superuser admin's routes only act on their own scope. Another scope's account gets 404, the same as a missing one. `GET /users/` takes `scope_filter`. Superusers act across scopes. The boundary is in the routes, not `UserService`.
- #81, part 3: `configure_scope(base_url=fn)`. A URL template starting with `/` gets the account's scope's base URL in front. Absolute templates are unchanged.
- #82: release 0.8.0. `master` fast-forwarded, tagged `v0.8.0` (`60336a0`).

**#83: migration 0007 on other schema shapes (v0.8.1)**
- #83, filed this session → #84: 0007 dropped the old unique indexes by their `create_all` names. intertainment-be built `users.users` from raw SQL, so its email uniqueness is the constraint `users_email_key`, and the upgrade failed. 0007 now finds single-column uniqueness on `email` and `username` by column in `pg_catalog`. The revision id is unchanged.
- Checked on PostgreSQL 16 against four schema shapes, including intertainment's real baseline: upgrade, downgrade and upgrade again all match the model (`pg_dump -s` diff empty).
- Released as 0.8.1 in #84. `master` fast-forwarded, tagged `v0.8.1` (`533fc7c`).
- The user tested 0.8.1 on three projects and closed #83.

## Decisions
- **Scopes are opt-in per app** (second commit of #79). Apps that don't call `configure_scope()` behave exactly as before, and can't end up with two accounts for one address.
- **Base URLs use a path-prefix rule** (#81), not a `{base_url}` placeholder: a template starting with `/` gets the base URL.
- **The scope boundary lives in the routes** (#80). Server code calling `UserService` is trusted, so Orbit's own member endpoints apply Orbit's checks.
- **0007 kept its revision id** in 0.8.1. On a `create_all` schema the result is identical, and the old file couldn't have succeeded on any other shape.

## Learned
- **Don't drop constraints or indexes by name in a migration a consuming app runs.** Apps build the package's tables in different ways (`create_all`, raw SQL, their own migrations), so the names differ. Find them by column in `pg_catalog`.
- **The SQLite suite can't catch this.** 356 tests passed on 0.8.0 while 0007 failed on a real app's Postgres schema. Check migrations against each consuming app's real schema shape, not only `create_all`.
- Of the consuming apps, five build the package tables with `create_all` at startup. intertainment is the one confirmed raw-SQL shape (see #84).
